# 部署指南

> 适用范围：docker-compose 一键部署（`docker-compose up --build`）。
> 结论：当前配置在本地开发正常，**直接搬上服务器有 5 个必修点**（不修则文件流转断开、RAG 报错、backend 起不来、前端连不上后端），另有若干建议项。

---

## 一、必修项

### 1. ai-service 的环境变量路径是"本地开发版"，容器里全错位

`ai-service/.env` 中的目录配置是相对本机开发目录的：

```ini
CHROMA_DIR=../backend/data/vector
UPLOAD_DIR=../backend/data/uploads
PROCESSED_DIR=../backend/data/processed
```

本地 dev 下 `../backend/data` 相对 `ai-service/` 目录解析，指向仓库根目录的 `backend/data/`，没问题。
但容器内 `WORKDIR=/app`，`../backend/data` 会解析成 `/backend/data`（不存在的目录）；而 docker-compose 将 `./backend/data` 挂载到了 `/app/data`。

后果：backend 写文件到 `/app/data/uploads`（backend/data ✓），ai-service 读写 `/backend/data/...`（✗ 什么都没挂）。**两服务不共享目录 → 上传→解析→下载整条链路断开**。这是最隐蔽也最致命的一处。

修复：在 compose 的 `environment:` 中覆盖（`environment` 优先于 `env_file`）。

### 2. Embedding 模型不在 Docker 镜像里

- `EMBEDDING_MODEL=./data/models/bge-small-zh-v1.5`（约 92MB）
- ai-service Dockerfile 只 `COPY app ./app`，模型未进镜像
- `.gitignore` 排除了 `ai-service/data/models/`（不入库）
- `HF_HUB_OFFLINE=1` 禁止联网下载

容器里跑 RAG（parse / qa / summary）会直接报模型找不到。
另外即使把模型拷进镜像，`./backend/data:/app/data` 挂载点会**遮住** `/app/data/models` —— 所以模型必须挂到独立路径（如 `/app/models`）。

### 3. 前端 `VITE_API_BASE` 是构建期烘焙的

`frontend/src/api/http.ts` 中：

```ts
baseURL: import.meta.env.VITE_API_BASE || 'http://localhost:3001/api',
```

`VITE_API_BASE` 在 `npm run build` 时被打进产物，而前端 Dockerfile 构建阶段没有传该变量 → 烘焙成 `http://localhost:3001/api`。
用浏览器访问 `http://服务器IP:3000` 时，浏览器会请求**用户自己电脑**的 localhost:3001 → 全部失败。

修复：Dockerfile 构建阶段加 `ARG VITE_API_BASE`，compose 构建时传 `build.args`。

### 4. CORS 默认只放行 localhost

`backend/src/config/env.ts` 默认值：

```ts
corsOrigins: 'http://localhost:3000,http://127.0.0.1:3000'
```

compose 里 backend 未设 `CORS_ORIGIN`。用 IP/域名访问前端 → 跨域被拒。
修复：compose 的 `environment` 里追加服务器 IP 或域名（逗号分隔）。

### 5. PostgreSQL（元信息事实源，backend 启动 fail-fast）

文件元信息与 LLM 设置已迁入 PostgreSQL（`files`/`settings` 表），backend 启动时连不上 PG 会**直接退出**（exit 1）。compose 已内置 postgres 服务 + healthcheck + `pg-data` 卷持久化，本地开发需本机原生 PG16（建库建用户见根目录计划的 Phase 0；默认连接串 `postgres://ai_office:ai_office@127.0.0.1:5432/ai_office`）。

**升级步骤**（旧版 Redis 元信息 → PostgreSQL）：无需手工操作。backend 首次启动自动建表（drizzle 迁移）并把 Redis 里的旧元信息一次性导入 PG（迁移标记写 `app_meta` 表 + Redis 兜底键），之后旧 Redis 键与 files.json 均降级为冷备份。⚠ 若启动日志提示「Redis 中未发现文件元信息（0 条）仍写入迁移标记」且旧数据确实存在，说明 Redis 数据缺失：删除 `app_meta` 的 `redis_files_imported` 行后重启即可重试。

Redis 已退位为限流计数 + ai 缓存（fail-open），连不上只告警不退出；docker 与本地开发**不可共用同一个 DATABASE_URL**（PG 里存的是环境相关的绝对文件路径，混用会下载 404）。

**备份策略变更**：备份对象变为 PG 数据（`pg_dump`；⚠ dump 含**明文 apiKey**，备份文件必须限制权限/加密）：

```bash
# cron 示例（每日 03:17）：
docker compose exec -T postgres pg_dump -U ai_office -d ai_office -Fc > /backup/ai_office-$(date +\%F).dump
# 恢复：
docker compose exec -T postgres pg_restore -U ai_office -d ai_office --clean < /backup/ai_office-YYYY-MM-DD.dump
```

## 二、强烈建议

| 问题 | 说明 |
|---|---|
| **8000 端口公网裸奔** | compose 将 ai-service 的 8000 暴露到公网且**无任何鉴权**，任何人可直接打 LLM 接口烧 API 余额。应只绑 `127.0.0.1` 或仅保留 3000/3001 |
| **无 .dockerignore** | frontend Dockerfile `COPY . .` 会把本地 500MB+ 的 node_modules 拷进构建上下文，首次构建极慢 |

可选优化（部署后）：

- `backend/data` 内上传文件只增不减，长期运行需定时清理策略
- 有正式域名 + HTTPS 需求时，建议 nginx 反代并托管前端静态文件，可彻底绕开 CORS 与 `VITE_API_BASE` 问题

## 三、修改方案

### 3.1 docker-compose.yml（完整改后版）

```yaml
version: "3.8"

services:
  postgres:
    image: postgres:16-alpine
    environment:
      - POSTGRES_USER=ai_office
      - POSTGRES_PASSWORD=ai_office
      - POSTGRES_DB=ai_office
    volumes:
      - pg-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ai_office -d ai_office"]
      interval: 5s
      timeout: 3s
      retries: 10
    restart: unless-stopped
    # 不映射端口：仅容器网络内可达

  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]   # AOF：限流计数 + ai 缓存（fail-open，无需强保）
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
    restart: unless-stopped

  ai-service:
    build: ./ai-service
    ports:
      - "127.0.0.1:8000:8000"        # 只绑本机，公网不暴露
    volumes:
      - ./backend/data:/app/data
      - ./ai-service/data/models:/app/models:ro   # 模型挂独立路径，避开 /app/data
    env_file: ./ai-service/.env
    environment:                      # environment 优先于 env_file
      - CHROMA_DIR=/app/data/vector
      - UPLOAD_DIR=/app/data/uploads
      - PROCESSED_DIR=/app/data/processed
      - EMBEDDING_MODEL=/app/models/bge-small-zh-v1.5
      - REDIS_URL=redis://redis:6379/1          # 缓存走 db 1，与限流（db 0）隔离
      - DATABASE_URL=postgres://ai_office:ai_office@postgres:5432/ai_office   # 只读 settings 表（fail-open）
    depends_on:
      redis:
        condition: service_healthy
      postgres:
        condition: service_healthy
    restart: unless-stopped

  backend:
    build: ./backend
    ports:
      - "3001:3001"
    depends_on:
      ai-service:
        condition: service_started
      redis:
        condition: service_started   # 仅顺序依赖：限流 fail-open，不阻断启动
      postgres:
        condition: service_healthy   # 元信息事实源，启动 fail-fast
    environment:
      - AI_SERVICE_URL=http://ai-service:8000
      - CORS_ORIGIN=http://localhost:3000,http://127.0.0.1:3000,http://<服务器IP>:3000
      - REDIS_URL=redis://redis:6379
      - DATABASE_URL=postgres://ai_office:ai_office@postgres:5432/ai_office
      - RATE_LIMIT_ENABLED=true
    volumes:
      - ./backend/data:/app/data      # 上传/结果文件（元信息存 PG，首启自动从 Redis 一次性导入）
    restart: unless-stopped

  frontend:
    build:
      context: ./frontend
      args:
        - VITE_API_BASE=http://<服务器IP>:3001/api
    ports:
      - "3000:3000"
    depends_on:
      - backend
    restart: unless-stopped

volumes:
  redis-data:
  pg-data:
```

> 说明：`<服务器IP>` 需替换为实际部署机的 IP 或域名。

### 3.2 frontend/Dockerfile（加一行 ARG + ENV）

```dockerfile
# ---------- 构建阶段 ----------
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY tsconfig.json ./
COPY src ./src
ARG VITE_API_BASE=http://localhost:3001/api   # 新增：构建期注入后端地址
ENV VITE_API_BASE=$VITE_API_BASE
COPY . .
RUN npm run build

# ---------- 运行阶段（静态托管构建产物）----------
FROM node:20-alpine
WORKDIR /app
COPY --from=build /app/dist ./dist
RUN npm install -g serve
EXPOSE 3000
CMD ["serve", "-s", "dist", "-l", "3000"]
```

> 注意：`ARG` 必须放在 `RUN npm run build` 之前才能生效。

### 3.3 frontend/.dockerignore（新建）

```
node_modules
dist
.env*
```

### 3.4 应用后的启动命令

```bash
cd ai-office-mvp
docker-compose up --build -d
# 浏览器访问 http://<服务器IP>:3000
```

## 附：原理速查

| 现象 | 原因 |
|---|---|
| 上传后解析/问答失败 | 两服务目录不共享（必修 1）或模型缺失（必修 2） |
| 页面能开但接口全挂（请求 127.0.0.1:3001） | `VITE_API_BASE` 烘焙成 localhost（必修 3） |
| 接口报跨域错误 | `CORS_ORIGIN` 未含访问地址（必修 4） |
| backend 启动即退出，日志报 PostgreSQL 连接失败 | postgres 未就绪/`DATABASE_URL` 配错（必修 5）；Redis 连不上只会告警不会退出 |
| 频繁请求后接口返回 429 | 网关限流触发（per-IP 固定窗口，`RATE_LIMIT_*` 可调） |
| 公网能直接访问 8000 端口 | compose 未绑 127.0.0.1（建议项） |
